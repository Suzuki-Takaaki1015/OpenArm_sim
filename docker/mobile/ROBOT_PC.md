# Happy mignon ロボットPC

`bash start.sh` の機体選択で **3** を選びます。毎回指定する場合は次のコマンドで起動できます。

```bash
bash start.sh --robot-version 3
```

起動後に Ubuntu で `oa-code` を実行すると、コンテナ内の一般ユーザーとして開発できます。開くフォルダーは `/workspaces/OpenArm_dev` です。

| ディレクトリ | 用途 |
| --- | --- |
| `external_ws/src/urg_node` | 北陽の実機用ROS 2ドライバー。シミュレーションではMuJoCoがスキャンを生成します。 |
| `happy_ws/src/main` | チームのROS 2パッケージ。各パッケージをここに作成・クローンします。 |
| `happy_ws/src/main/openarm_demos` | OpenArmのデモ |
| `happy_ws/src/main/happy_robot` | 腕・オドメトリ・レーザーの受信確認ノード |

編集内容とビルド結果はホストの `.openarm/happy_robot_pc/` に保存されます。外部ワークスペース、チームワークスペースの順で初回ビルドします。新しいチームパッケージを追加した後はコンテナ端末で実行してください。

```bash
cd /workspaces/OpenArm_dev/happy_ws
colcon build --symlink-install
source install/setup.bash
```

### オペレーターによる操作

シーンパネルの「ユーザー移動制御モード」をオンにすると、緑色の操作欄で W/S が前後、A/D が左右、Q/E が左・右旋回です。複数キーを同時に押せます。離すと減速し、Esc・フォーカス移動・チェック解除で手動モードを終了します。内部の手動入力は20 Hz、通常の指令は手動入力終了から0.5秒後に受け付けます。

「アーム姿勢」で対象の腕を選び、「現在角を取得」してから J1〜J7 を度単位で編集します。「計画して実行」はMoveItが衝突をチェックしながら経路を計画して実行します。「中止」で実行中の目標を取り消せます。運転を停止してから操作してください。「初期姿勢を入力」は全関節0度を入力欄にセットします。コードは `happy_ws/src/main/happy_posture` にあります。

```bash
oa-ros run happy_posture posture right --read
```

モード3の胸部D435iは、白い胸部カバー前面の切り欠き中央に収めています。カメラ前面中心は `openarm_body_link0` 基準で X=57、Y=0、Z=631 mm、光軸は前方から下向き15°です。これは公式写真と機体CADに合わせたシミュレーション用の取り付け寸法です。RGB・深度・点群の光学フレームもこの取り付け姿勢を使用します。[Enactic公式の紹介映像](https://www.youtube.com/watch?v=6ZLM6f8kF4Q)

### 胸部D435iと台車D455のRGB-D

シーンパネルの「カメラ配信」→「配信開始」で2台同時に有効になります。運用用RVizで Chest D435i RGB-D または Chassis D455 RGB-D にチェックすると色付き点群を表示できます。画像を見るには RViz の Add → Image で下記の image トピックを選択します。

トピック先頭は胸部が `/camera/d435i`、台車が `/camera/d455` です。

| 続く名前 | 型 | 内容 |
| --- | --- | --- |
| `/color/image_raw` | Image (rgb8) | RGB画像 |
| `/depth/image_rect_raw` | Image (16UC1) | 深度光軸に沿った距離、mm、無効値0 |
| `/aligned_depth_to_color/image_raw` | Image (16UC1) | RGBの視点・解像度に合わせた深度 |
| `/color/camera_info`, `/depth/camera_info`, `/aligned_depth_to_color/camera_info` | CameraInfo | 対応する画像の内部パラメーター |
| `/depth/color/points` | PointCloud2 | 色画像に対応する organized XYZRGB、m、無効な点はNaN |

両機種のRGB・深度・点群は同じシミュレーション時刻を持ちます。点群は購読時に生成し、カラー光学フレームで右が+X、下が+Y、前が+Zです。D435iは従来の `camera_color_optical_frame` / `camera_depth_optical_frame` と `/camera/camera` でも画像を利用できます。D455は `d455_color_optical_frame` / `d455_depth_optical_frame` です。既定2 Hz。車体CAD正面の筐体とRealSenseの公称光学オフセットからD455の位置を設定しています。RGB-Dは理想ピンホールモデルで、IMUや実機の測距ノイズは今回の対象外です。

```bash
oa-ros topic hz /camera/d455/depth/color/points
```

### 台車の制御

| トピック | 型 | 用途 |
| --- | --- | --- |
| `/cmd_vel` | geometry_msgs/msg/Twist | 車体基準。前進はlinear.x、左移動はlinear.y（m/s）、左旋回はangular.z（rad/s）。指令が0.5秒途切れると減速します。 |
| `/odom` | nav_msgs/msg/Odometry | シミュレーションでの車体姿勢・速度。TFはmap → odom → base_linkです。シミュレーション用worldはodomに固定します。 |
| `/scan` | sensor_msgs/msg/LaserScan | laserフレーム、Best Effort。UTM-30LX相当の270度、0.25度間隔、1081点、距離0.1～30 m、シミュレーション時間で40 Hz。走査面の高さはCAD外形からの推定値です。 |

停止した台車で腕とセンサーの疎通を確認できます。

```bash
oa-ros run happy_robot robot_status
```

周囲を確認して、コンテナの端末で次を実行すると左方向に短く移動します。左右の腕とグリッパーはモード2と同じコントローラーで操作します。

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist '{linear: {y: 0.1}}'
```

[北陽 UTM-30LX仕様](https://www.hokuyo-aut.co.jp/search/single.php?serial=21) ・ [実機用urg_nodeの採用リビジョン](https://github.com/ros-drivers/urg_node/tree/1b3e5502ca162a2fa03c591b04ce97c9cdb695a6)


### 台車の走行速度

「台車の手動運転」で速度を選び、「ユーザー移動制御モード」をオンにします。WASDは前後左右、Q/Eは旋回です。斜め移動でも並進の上限は同じです。移動キーをすべて離すと減速して停止します。

| 手動設定 | 並進指令 | 旋回指令 |
|---|---:|---:|
| 低速 | 0.18 m/s | 0.5 rad/s |
| 標準（初期値） | 0.40 m/s | 0.9 rad/s |
| 高速 | 0.60 m/s | 1.2 rad/s |

Nav2の標準設定は最大0.40 m/s・0.9 rad/sです。GUIの速度選択は手動運転に適用されます。調整済みの `/workspaces/OpenArm_dev/navigation/nav2.yaml` は次回起動にも引き継がれます。

### 大会環境を保存して切り替える

生活環境エディターの「環境を保存」で名前を付けます（例：大会A・予選、大会A・決勝）。「新規」から別の部屋を作成でき、保存した各環境はコンテナ再作成後も残ります。上段の一覧で環境を選び「この環境に切替」を押すと、その部屋で機体を初期位置から再起動します。「編集用に開く」は走行を継続したまま別の環境を編集します。既存の rooms/*.json も一覧に表示します。別のPCへ移すときはホストの .openarm/happy_robot_pc/rooms と navigation の両方をコピーしてください。

環境を削除するには、上段の一覧から部屋を選び、**環境を削除…** を押して部屋名を確認します。ライブラリの保存版だけが削除されます。使用中の部屋はそのまま走行でき、編集中の配置は「環境を保存」で再保存できます。作成済みのNav2地図も保持されます。

地図作成・Nav2パネルには現在の家具配置に合う地図だけが表示されます。異なる配置の環境に同名の地図を作成できます。以前選んだ地図と自己位置推定／マッピング設定は環境の配置ごとに復元します。家具配置を変えた場合は新しい地図を作成してください。

### 生活環境エディター

モード3をGUI付きで起動し、「シーンとセンサー」パネルの **生活環境エディターを開く** を押します。別ウィンドウで壁・机・椅子・収納棚を選び、平面図をクリックして配置してください。ドラッグで移動し、右欄で座標、角度、寸法を指定できます。線は1 m間隔（広域表示は5 m）、スナップは10 cmです。

「書き出し」「ファイル取込」でJSONファイルを受け渡せます。「部屋を適用して再起動」を押すと、現在の走行や腕の動作を終了し、初期位置から新しい部屋で起動します。適用中の部屋は次回起動にも引き継がれます。空の部屋を適用すると家具をすべて外せます。家具は固定され、机・椅子の脚間は空洞です。

**机に小物を置く** — 平面図で机を選び、右欄の「机の上を編集…」を開きます。ボトル・直方体・飲料缶から選び、拡大した天板上をクリックします。同じ種類を複数置けます。物体をドラッグするか、机の中心からの X・Y（m）と角度を指定し、「机に反映」を押してください。物体が重なる位置や天板からはみ出す位置は選べません。

部屋と一緒に初期配置を保存できます。エディターで机を動かすと物体も一緒に移動します。「部屋を適用して再起動」した後は各物体に重力と衝突が働き、動いた位置がシミュレーション側のRVizにも反映されます。机上物体だけを編集した場合は、同じ家具配置のナビゲーション地図を引き続き使用できます。

保存先はコンテナ内の `/workspaces/OpenArm_dev/rooms`、ホスト上の `.openarm/happy_robot_pc/rooms` です。

### センサー地図と Nav2

モード3では運用用RVizも開きます。初期視点は機体中心の3Dです。ツールバーの **Move Camera** で、描画領域を左ドラッグすると周囲360°の回転と上下の視点変更ができます。ホイールで拡大・縮小します。地図上で初期姿勢やゴールを指定するときは、**Views** パネルの **Map 2D** をダブルクリックすると真上から確認できます。**Robot 3D** をダブルクリックすると機体中心の初期視点に戻ります。

自律走行の前方は、2D LiDAR（UTM-30LX）がある側（`base_link` の +X、`/scan` の0度）です。横や後方への経路では先に旋回し、LiDARを進行方向に向けて前進します。ゴールではRVizの矢印で指定した最終姿勢に合わせます。標準の復旧動作にはその場旋回・待機・コストマップのクリアを使用します。手動運転のWASDは引き続き前後左右へ動けます。

以前の標準 `nav2.yaml` は起動時に更新されます。独自設定を使用している場合は、コンテナ内の `/opt/happy/navigation/nav2.yaml` の `FollowPath`、`progress_checker`、`velocity_smoother` と `bt_navigator` の既定ツリー2項目を比較し、必要な項目を開発ワークスペースの設定に反映してください。

こちらは機体・UTM-30LX・センサーから作った地図・経路を表示します。部屋エディターで壁などを配置して適用し、手動運転で周囲を観測します。起動直後はSLAM Toolboxのマッピングモードです。特徴の少ない空の部屋では地図を作れないことがあります。

**MID-360Sで室内の形を見る**　シーンパネルの **MID-360S 点群 → 配信開始** を押します。未装着なら自動で取り付けてシミュレーションを再起動します。センサー用RVizの **Displays → MID-360S 3D LiDAR** が、レーザーの当たった床・壁・家具を高さ別の色で表示します。色は地図座標での高さを表します。

点群は直近1秒分を重ねて表示します。動く物体の残像を減らしたいときは、同じ項目の **Decay Time** を短くしてください（0で最新の1回分）。**Views → Orbit** で視点を回せます。位置推定前で `map` のTFがまだ無いときは **Global Options → Fixed Frame** を一時的に `odom` にすると点群を確認できます。Nav2で初期姿勢や目標を指定する際は `map` に戻してください。

1. シーンパネルの「地図作成・Nav2」で地図名を入力し「地図を保存」を押します。
2. 「保存地図で起動」で機体を初期位置に戻し、地図サーバーとAMCLを起動します。位置がずれている場合は運用用RVizの「2D Pose Estimate」で位置と向きを指定します。
3. 手動運転を解除し、運用用RVizの「Nav2 Goal」で目的地と向きをドラッグします。Navigation 2パネルでキャンセルできます。
4. 「新規マッピング」で地図作成に戻ります。別の部屋を適用した場合は対応する地図を作成または選択してください。

VS Codeで開く `/workspaces/OpenArm_dev/navigation/` に `slam.yaml`、`nav2.yaml`、`by_room/<配置ID>/maps/<地図名>/map.yaml`（従来の地図は `maps/<地図名>/map.yaml`） と地図画像が残ります。設定を編集して同じモードで再起動すると反映します。局所経路制御はRegulated Pure Pursuit、AMCLはOmniMotionModelです。速度・加速度上限は台車に合わせています。コストマップの初期半径0.30 mは台車の近似で、腕を展開する場合は実寸と運用姿勢に合わせて調整してください。シミュレーションのオドメトリは物理モデルの姿勢を使用します。地図と障害物観測は実際の /scan 入力から生成します。
