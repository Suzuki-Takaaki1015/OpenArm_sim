# OPL 2026 training assets

## Source and limits

The object set follows [OPL General Rules](https://github.com/RoboCupAtHomeJP/AtHome2026/blob/d893b1db7432565a054be0da7ce09a2495425c5e/rules/OPL/gr.md), which selects Category A of the [DSPL object PDF](https://github.com/RoboCupAtHomeJP/AtHome2026/blob/d893b1db7432565a054be0da7ce09a2495425c5e/rules/DSPL/dspl_2026_object_list.pdf).
The catalog covers 34 PDF rows: 1, 2, 10–20, 22, 24–43.
Do not substitute the stale OPL/sd object list.

Furniture names come from the [published GPSR arena](https://github.com/RoboCupAtHomeJP/AtHome2026/blob/d893b1db7432565a054be0da7ce09a2495425c5e/rules/DSPL/sd/arena_gpsr.pdf): Bed, Bookcase, Coat rack, Side Table, Trash Bin, Dining Table, Dishwasher, Microwave, Cabinet, Table, Washing Machine, Coffee Table, Couch, Chair.
The drawing does not establish a metric layout. Furniture is optional, initially hidden, and individually placed; no official room geometry is claimed.

15 rows reuse existing YCB meshes, mass metadata and collision decomposition (see YCB.md). The other 19 rows use explicitly approximate rigid shapes. Their dimensions and masses in opl_assets.py are project defaults, not official measurements.
Green tea and milk use estimated filled mass; the Red Bull can uses estimated empty mass. No fluid physics.
The bag is unspecified in the rules until setup day, so its geometry is a placeholder. The clothes row provides 12 separately placeable folded rigid pieces; select 8–12 for scene composition. These do not reproduce deformable laundry.
Cups, tray, bag and basket use compound open collision geometry. New proxy contacts use a 4 ms time constant and priority 1 to reduce thin-wall tunnelling at the 2 ms physics step. Existing YCB concave decomposition limitations remain.
Appliances are fixed open-front shelving proxies: no moving doors, washing, heating or water.
The linked Kachaka Word supplement was not retrieved; its special rules are unverified. No mobile base or Kachaka control is implemented.

## GUI

Open **OPL 2026 物体・家具を開く** in the scene panel. Search by official ID, English name or key.
Place furniture first using world X/Y and yaw; it stands on the floor and remains anchored.
Select a support (worktable, furniture top, numbered shelf, seat or bin interior), then place an object by world coordinates or random placement.
Shelves are numbered from the bottom. Surface height is automatic.
Delete supported objects before moving/hiding furniture. Each object key represents one instance; the clothes row has 12 keys.
All assets are shared by OpenArm 1.0 and 2.0.

Coordinates are metres; yaw in the GUI/CLI is degrees. Accepted ranges are X/Y ±5 m and yaw ±360°.
Placement checks finite values, support bounds including the rotated object footprint, robot/object/furniture collisions, and restores prior state if rejected.
An occupied support association remains conservative even when an object falls or is moved by a member module; remove/re-place the object to clear it.
Support selection is not reachability planning. Stop arm motion before changing a scene.

MuJoCo and MoveIt use the same new primitive shapes. Furniture is anchored using MuJoCo mocap bodies; camera snapshots include those poses as well as dynamic object qpos.
MoveIt updates follow the existing asynchronous scene synchronizer. Wait for scene updates before planning. Attached objects continue to be managed by the member grasp module.

## Example commands

Execution location: **inside the running container**, with its ROS environment loaded.

Place the coffee table at a selected floor position:

```bash
python /opt/openarm/app/scene_cli.py opl_coffee_table-place --x 1.2 --y 0 --yaw 0
```

Place a lemonade proxy on its top:

```bash
python /opt/openarm/app/scene_cli.py opl_lemonade-place --x 1.2 --y 0 --yaw 0 --support opl_coffee_table:top
```

Remove the object:

```bash
python /opt/openarm/app/scene_cli.py opl_lemonade-off
```

Remove the coffee table:

```bash
python /opt/openarm/app/scene_cli.py opl_coffee_table-off
```

Core source changes require rebuilding the image. See the development task result for tested versions and validation evidence.
